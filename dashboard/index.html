  • pass5. reference checked against upstream
    the answer key is a plain float64 sum of the same weights, and every bin total also adds up to the grand total.
    reference is numpy 2.5.3 float64 sequential sum of the same float32 weights. grand total of the nki bins 262003.621254 against reference 262003.621367. the tensor add kernel and the simulate call follow the neuron docs quickstart and nki.simulate_kernel pages read live on 2026-09-09.
  • pass6. four summation orders, one tolerance
    the card and the simulator add the same numbers in a different order, and both stay inside the bound.
    sequential, reversed, chunked and the nki simulator disagree in 3954 of 4096 bins, at most 13 ULP apart. the nki result is bit exact with neither the sequential nor the chunked numpy sum. the 432 ULP bound covers all four. on the card the same kernel is bit exact with the numpy sequential sum at every seed, while the simulator matches neither order, so the two disagree in about 78 percent of bins by at most 10 ULP.
  • pass7. the chosen bound still catches a wrong kernel
    a kernel that drops one weight per bin fails almost every bin under the same bound the mi300x audit chose.
    the bound is 432 ULP, rel 2.58e-05, carried over from the mi300x audit. the correct kernel passes 4096 of 4096 bins. a kernel that drops the last of 128 weights in every bin fails 4090 of 4096 bins, median error 86472 ULP (rel 7.64e-03). the 6 bins that pass dropped a weight under about 3e-4.
  • pass8. the kernel ran on a NeuronCore
    the same kernel ran on a trainium card at four seeds, and the card answered every time.
    the kernel ran on one NeuronCore of a trn1.2xlarge at seeds 3, 7, 11 and 19, plus a repeat at seed 3 and a run pinned to the second core. wall time on the card is 1.36 to 1.44 s against 0.018 s in the simulator, and neither number is a kernel speed, because both include compile and dispatch. a speed ranking still needs a timed harness.
  • pass9. the simulator and the card disagree, and by how much
    the same kernel on the same input returned different numbers in the simulator and on the card.
    four seeds, 4096 bins each, with a sha256 of the weight bytes recorded on both paths and matching on every pair. between 3175 and 3221 of 4096 bins differ, the worst gap is 10 ULP and the median is 1 ULP, and 0 bins go over the 432 ULP bound on either path. the simulator sits closer to the float64 reference, 2 ULP worst against the card's 8, because the card reproduces the sequential order and the simulator does not.
  • pass10. the card repeats itself, and both cores agree
    running the same seed twice on the card returned the same 4096 numbers, and so did the other core.
    a grader that cannot reproduce a number cannot fail anyone with it. the same seed run twice on one NeuronCore returned 4096 of 4096 bins identical, and the run pinned to the second core returned 4096 of 4096 identical to the first. so the only divergence is against the host simulator, and it is bounded.
